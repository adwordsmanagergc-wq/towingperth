# towingperth.com

Website for **Quik Tow & Transport**, 24/7 towing across Perth. Rebuilt from the old Google Sites site as a fast static site built with Astro and Tailwind, deployed on Vercel.

## Quick start

```bash
npm install
npm run dev            # http://localhost:4321
npm run build          # writes dist/ (prebuild regenerates redirects and lints content)
npm run preview        # serves dist/ with vercel.json redirects applied, on :4322
```

## How the site is organised

| What | Where |
| --- | --- |
| Business facts (phone, TODO email/ABN/analytics IDs) | `src/config/site.ts` |
| Services (5 pages) | `src/content/services/*.md` |
| Regions (5 hubs) | `src/content/regions/*.md` |
| Suburbs (one file each) | `src/content/suburbs/*.md` |
| Dangerous roads | `src/content/roads/*.md` |
| Homepage and general FAQs | `src/data/faqs.ts` |
| Page templates | `src/pages/` |
| Components (Button, CallButton, TrustChip, ServiceCard, SuburbGrid, FAQ, CTASection, Breadcrumbs...) | `src/components/` |
| JSON-LD builders | `src/lib/schema.ts` |
| Title and description templates | `src/lib/seo.ts` |
| Writing rules for all copy | `docs/content-style-guide.md` |

### Adding a suburb

1. Add `{ slug, region }` to `NEW_SUBURBS` in `scripts/lib/legacy-map.mjs`, then run `npm run audit:suburb-index`.
2. Create `src/content/suburbs/<slug>.md` following `docs/content-style-guide.md` (copy an existing suburb for the front matter).
3. Run `npm run check:content <slug>`. It checks word counts, links, nearby slugs, banned phrases and sentences copied from other pages.

The page, its title and description, schema, sitemap entry, region hub listing, `/areas` listing and `llms.txt` entry are all generated.

## SEO and migration

- **Redirects:** every URL from the crawl (`content-audit/urls.csv`) gets a 301 in `vercel.json`, generated by `npm run redirects:generate` using the mapping in `scripts/lib/legacy-map.mjs`. The generator fails if any old URL has no mapping.
- **Redirect test:** `npm run build && npm run preview`, then `npm run test:redirects`. Against a Vercel preview: `npm run test:redirects -- --base https://<preview>.vercel.app`.
- **Site audit:** `npm run check:site` checks every built page for title (60 chars max) and description (155 chars max) lengths, duplicates, one H1, canonical, OG/Twitter tags, breadcrumbs, labelled form fields, image alt text, dashes in copy, broken internal links, and JSON-LD validated against the schema.org vocabulary (types, properties and Google's required fields).
- **Lighthouse (mobile):** `npm run lighthouse` (reports land in `lighthouse-reports/`).

## Content audit

`content-audit/` holds the crawl of the old site (`urls.csv`, `pages.json`), duplicate and mismatch findings (`duplicates.json`, `SUMMARY.md`) and competitor research (`competitors.md`).

## Quote form

Switched off for now (`quoteFormEnabled` in `src/config/site.ts`): quote buttons open an SMS instead. When on, the form posts to `api/quote.js` (a Vercel function), which works without JavaScript and emails the request through [Resend](https://resend.com). Set `RESEND_API_KEY`, `QUOTE_TO_EMAIL` and `QUOTE_FROM_EMAIL` in the Vercel project. A honeypot field filters bots.

## Analytics

Set `gtmId` (or `ga4Id`) in `src/config/site.ts`. Tags load on first interaction or after 3.5 seconds, so they don't slow the page. These events are pushed to `dataLayer` for Google Ads conversion import:

- `click_to_call` with `page_path`, `link_position` and `link_url`, on every `tel:` link
- `sms_click`, on every `sms:` link
- `quote_form_submit` with `form_position`
